## Why this matters

The app is pinned to Next.js `16.2.10`, which is below the patched floor `16.2.11`. Production advisories for this range include unauthenticated disclosure of internal Server Function endpoints, Server Actions DoS, and Image Optimization SVG DoS. This repo uses App Router + many `"use server"` modules under `lib/actions/*`, so the Server Actions advisories are reachable. Patching is a routine bump with high security leverage before real-user beta traffic.

## Steps

### Step 1: Bump package versions

In `package.json`, set both:
- `"next": "16.2.11"` (or newer patch in the 16.2.x line if already published and still recommended by `pnpm audit`)
- `"eslint-config-next": "16.2.11"` (match `next`)

Keep versions aligned with each other.

**Verify**: `node -e "const p=require('./package.json'); console.log(p.dependencies.next, p.devDependencies['eslint-config-next'])"` → both print `16.2.11` (or the chosen patched pair)

### Step 2: Refresh lockfile

Run: `pnpm install`

**Verify**: `pnpm why next` shows resolved version ≥ `16.2.11`; `pnpm-lock.yaml` updated

### Step 3: Verify suite

Run in order:
1. `pnpm lint`
2. `pnpm typecheck`
3. `pnpm test`
4. `pnpm build` (if build fails solely because `NEXT_PUBLIC_SUPABASE_URL` / anon key / `DATABASE_URL` are unset, set them from existing `.env.local` for the local run — never commit secrets. If build fails for a code reason unrelated to the bump, STOP.)

**Verify**: all exit 0

### Step 4: Confirm advisories cleared for Next

Run: `pnpm audit --prod 2>&1 | rg -n "next|16\\.2\\.1|GHSA-" | head -40`

**Verify**: no remaining advisory that lists vulnerable versions `>=16.0.0 <16.2.11` for package `next`. Other unrelated advisories may remain — do not fix them here.
